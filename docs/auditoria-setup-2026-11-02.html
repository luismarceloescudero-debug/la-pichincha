Lo que falta o mejora

HallazgoPor qué importa (simple)PrioridadCómo arreglarlo
.claude/settings.json no tiene bloque permissions (ni allow, ni deny, ni ask).Es como una casa sin cerraduras: todo depende de que cada vez alguien conteste "sí" o "no" a mano. Y si siempre se contesta "sí", nada frena nada.AltaAgregar deny para leer/editar .env* y .dev.vars del Worker, ask para git push, y allow para node --test, python -m unittest y git status/diff/log.
guardia.py no mira secretos ni git push a main, --force o reset --hard; solo publicación, tildes y archivos generados.Hoy frena que se publique en Telegram por error, pero no que se borre historia o se suba una clave. Lo peor es justo lo que no se puede deshacer.AltaSumar patrones en decidir: git push con --force/-f o hacia main, reset --hard; y en decidir_archivo rutas .env y .dev.vars. Agregar los casos a test_hooks_claude.py.
La continuidad (privado/continuidad.md) sigue fuera del repo; no existe docs/continuidad.md (pendiente desde la auditoría del 01/11).Si el trabajo sigue en otra máquina o en la nube, el modelo nuevo llega sin saber qué se venía haciendo y puede rehacer cosas.AltaCrear docs/continuidad.md (sin datos sensibles) y que CLAUDE.md apunte a él como respaldo.
No hay .mcp.json en el repo.Las herramientas (Playwright, Chrome DevTools) están solo en la PC de una persona; otra sesión o máquina no las tiene.MediaCommitear un .mcp.json mínimo con playwright (instalado con npm -g y node, no npx, por el timeout de 30 s).
Los hooks de progreso viven en settings.local.json con rutas absolutas de C:/Users/Usuario; launch.json (ignorado) apunta al worktree 044-nombres-legibles.Si cambia la carpeta o la máquina, los hooks fallan en silencio y la vista previa apunta a algo que ya no existe.MediaUsar variables ($HOME) en esas rutas y borrar la entrada web-044 de launch.json.
Falta un hook que avise al terminar si quedaron cambios sin commitear (regla global de cierre).La regla "nada queda sin commitear" depende de acordarse; un aviso automático no se olvida.MediaHook Stop en settings.json que corra git status --porcelain y avise si hay algo.
test_del_archivo.py solo prueba js/*.js y .py de la raíz; un tiendas.json o datos.json roto no se detecta al editar.Una coma de más rompe todo el sitio, y la CI se entera recién después de subir.MediaAmpliar el hook: si el archivo editado es un *.json de la raíz, hacer json.load y devolver código 2 si falla.
Hay ~3.800 líneas de SKILL.md de terceros commiteadas (speckit-* x10, reverse-engineer-anything, web-quality-audit, find-skills, code-review, el propio recommender).Sus descripciones se cargan en cada sesión y gastan contexto, aunque casi nunca se usen en este repo.BajaDejar en el repo solo lo del proyecto (cerrar-pr, medir-indice, speckit) y pasar el resto a nivel usuario (-g).
No hay subagentes (.claude/agents/ no existe), aunque el Worker maneja los únicos secretos.Una revisión de seguridad aparte del código del Worker detecta cosas que quien lo escribió ya no ve.BajaCrear .claude/agents/security-reviewer.md limitado a worker/src (ya recomendado el 01/11).
